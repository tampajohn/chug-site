## 01 · quickstart

Quickstart

One command installs the latest release — platform detected, checksum verified, no sudo:

curl -fsSL https://chug.sh/install.sh | sh

What it puts where:

  • ~/.local/bin/chug — the binary, and nothing else. No config files, no daemon, no dotfiles; every run's state lives in the repo it ran in, under .chug/.
  • If ~/.local/bin is not on your PATH, the installer prints the one export line to add.

No release for your platform, or you want to live on source:

git clone https://github.com/tampajohn/chug && cd chug
cargo install --path .

First run

chug run takes a spec file with a check: line and a goal, then drives a fixed loop until that check exits zero:

cat > SPEC.md <<'EOF'
# Fix the flaky login test

The login test passes alone but fails roughly one run in five.
Make it deterministic.

check: cargo test --test login
EOF

chug run --spec SPEC.md --goal "Make the login test deterministic" \
  --max-iters 40 --max-minutes 120

The check: line is the whole contract: a run only ends when the check exits 0 on a re-run, never when the model says it is done. Point --model at any provider that speaks the Anthropic Messages API — ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN in the env, or your existing ~/.claude/settings.json (chug reads it when the env is empty).

No spec yet? chug run --goal "Fix the flaky login test" --auto-spec drafts one for you, dry-runs its check, and refuses a check that cannot pass on the current tree. chug chat is the interactive sibling; --tui adds the live dashboard to either.

The continuous loop

Single runs are one item. The supervisor makes it a queue that works itself: clone the repo and start loopd.sh — cycles run back-to-back, each wrap feeding the next cycle, all state in files:

git clone https://github.com/tampajohn/chug && cd chug
nohup ./loopd.sh > /dev/null 2>&1 &   # start (detached)
./loopd.sh status                     # liveness + recent cycle activity
./loopd.sh stop                       # exits after the current cycle

What healthy looks like (first 10 minutes)

  • the run prints ▪ iter NN … lines — reading, editing, running bash — and every event appends to .chug/events.jsonl
  • chug: budget low — N iteration(s) remain as the ceiling nears; a budget death leaves LEDGER.md intact and prints a resume line
  • goal_complete appears only after the spec's check: re-runs and exits 0; a rejected claim keeps the loop in charge
  • chug ledger prints LEDGER.md — the run's external memory
  • the first eval lands as a fresh EVALUATION.md body — the loop examining its own recent cycles, dated same-UTC-day at the top
  • under loopd: .chug/loopd/loopd.log gains one cycle OK line per completed cycle (plus a cheap-exit disposition line on empty days — a $0 cycle), .chug/loopd/cycle-*.log holds each cycle's stream, and ./loopd.sh status answers "is it alive"

## 02 · mental-model

Mental model

chug is a driver-in-code loop, not a chat prompt. Five pieces carry everything; every feature lands inside one of them.

  • The loop is a program. Continue/stop is the driver's call, never the model's: the anti-stall kick, the stuck tripwire, budget-low warnings, and the same-cwd driver lock live in the binary. The model proposes; the loop disposes.
  • LEDGER.md is external memory. Updated every iteration, injected into every turn — transcript trimming can never lose progress. A fresh run archives and reseeds it; --resume keeps it.
  • TODO.md + specs/ are the work queue. One row per item, one spec file per row, a mechanical check: line per spec. The supervisor reads the same files every cycle — the queue is the interface, not a chat channel.
  • Gates + validators are the trust boundary. Build, clippy, the full test suite, and an adversarial validator from a different model family stand between "the model says done" and "the work lands"; mutant runs prove the tests can fail.
  • Cheap-exit / dormancy is the cost boundary. An empty day takes a $0 mechanical cheap exit instead of launching a model; an empty queue goes dormant — a weekly read-only audit instead of manufactured work.
        ┌─────────────────────────────────────────────┐
        │  TODO.md + specs/        the work queue     │
        └──────────────────────┬──────────────────────┘
                               ▼
   ┌───────────────────────────────────────────────────┐
   │          the driver loop  (a program)             │
   │                                                   │
   │   re-read SPEC + GOAL + LEDGER.md each iteration  │
   │            │                                      │
   │            ▼                                      │
   │     one model turn (read / edit / bash / grep)    │
   │            │                                      │
   │            ▼                                      │
   │   claim: goal_complete → the check: re-runs       │
   │        │                  │                       │
   │     exit 0            nonzero ──► keep chugging   │
   │        ▼                                          │
   │   gates: build + clippy + suite + validator       │
   └──────────────────────┬────────────────────────────┘
                           ▼
        ┌─────────────────────────────────────────────┐
        │  wrap: merge + push + harvest → next cycle  │
        └─────────────────────────────────────────────┘

LEDGER.md rides beside the loop the whole way down — rewritten every iteration, so a trimmed or crashed run resumes from the page, not from the model's memory.

## 03 · first-feature

Your first feature

The loop works a file-based queue, so filing a row is the assignment. The whole arc:

  1. Write a spec — specs/tNNN-short-slug.md: the concern, the requirements, the tests, and a mechanical check: line. The loop's goal gate re-runs that check and accepts nothing but exit 0.
  2. File the TODO row — one line in TODO.md: id, title, spec path, priority, status open. That row is the contract; there is nothing to assign to anyone.
  3. Let the loop pick it up — under ./loopd.sh the next cycle takes the highest-priority open row; or run it directly: chug run --spec specs/tNNN-short-slug.md --goal "Land X".
  4. Read the harvest — the landed commit, the validation verdict, the merged LEDGER, and the artifacts under .chug/ (events, ledgers, decision records). The wrap is the paper trail.

What a good first item looks like

  • Small — roughly 150 changed lines or less. Review time and the validator's low-stakes lane both scale with diff size.
  • Checkable — the spec's check: is a command, not a vibe: a test that fails before and passes after, a script that exits nonzero on the bug and zero on the fix.
  • Outward — docs, a runbook, a CLI surface, a rendered page: work whose result a reader can see. It is also the loop's own favorite food — this page and every runbook were filed and landed this way.

Bad first items: sweeping refactors (unbounded), anything without a mechanical check (the loop cannot prove done), and infrastructure your teammates have not agreed to (the queue is public — file it, propose it, let it be picked up deliberately).

## 04 · faq

FAQ

What does this cost?

The public numbers are on the site: the cost tile on the home page and the per-day table on the docs page — daily spend, baked in at every sync. The loop's own cost boundary: empty days take a $0 mechanical cheap exit, a drained queue goes dormant (a weekly read-only audit, not manufactured work), and routine cycles ride the cheaper routine model unless the day's freshness rule escalates.

Is it safe to point at my repo?

The trust boundary is mechanical, not hopeful. Every shell call passes the risk gate — destructive calls are blocked with an error the model can route around — and .chug/hooks.json can veto any tool call, while .chug/permissions.json deny-rules fail closed. Tools are sandboxed to the run cwd, and the goal gate is the spec's check: re-running, never a model's claim. The README's risk gate, hooks, and permissions sections name every knob.

Do I need an Anthropic account?

No. chug speaks the Anthropic Messages wire protocol; point ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN at any provider that speaks it. The repo's own loop runs kimi for judgment calls and glm for routine phases — per-phase routing is a mechanical rule in the supervisor (./loopd.sh routing prints what the next cycle would get), never a model's choice.

How do I uninstall?

./loopd.sh stop (and remove the launchd plist, if you installed one), delete the binary — rm ~/.local/bin/chug, or cargo uninstall chug if you installed from source — and delete any per-repo state you do not want (the .chug/ directory inside each repo it ran in). Nothing else was installed.
